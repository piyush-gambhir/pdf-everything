**pdf-everything** is an open-source PDF platform with nineteen operations, a
browser console, and a versioned REST API. The console is a normal API client:
anything you can do visually can also be automated from your own application.

## Choose how you want to use it

| Path              | Best for                                                     | Start here                                  |
| ----------------- | ------------------------------------------------------------ | ------------------------------------------- |
| Console           | Trying tools, occasional document work, and learning options | <ConsoleLink>Open the console</ConsoleLink> |
| REST API          | Product integrations, automations, and backend workflows     | [Quickstart](/docs/quickstart)              |
| Self-hosted stack | Private documents, custom policy, and infrastructure control | [Deployment](/docs/deployment)              |
| Worker images     | Reusing only the execution layer behind your own gateway     | [Workers](/docs/workers)                    |

## The four deployable surfaces

| Surface        | Responsibility                                                                 |
| -------------- | ------------------------------------------------------------------------------ |
| **Web + docs** | Product site and this documentation. It is a static Next.js export.            |
| **Console**    | Static UI for all nineteen tools. It contains no PDF implementation.           |
| **Nest API**   | Public `/api/v1/**` contract, validation, uploads, stored results, and policy. |
| **Workers**    | PDF core execution and Chromium-based HTML/Markdown rendering.                 |

## Core guarantees

- The console and external clients use the same API contract.
- Heavy PDF and browser dependencies stay out of the public API process.
- Workers can scale independently according to their memory and CPU profiles.
- Worker images are public, but production execution routes should remain
  private or authenticated.
- Most operations can return a PDF directly or a temporary file reference.
- Validation failures and execution errors use RFC 9457-style problem
  responses.
